## The shape this round kept hitting

`""` is the plugin's own encoding of "no target". `exec_run.build_response`
writes `connection = conn or ""` and `database = shown_db or ""`, a directive
with a blank value captures as `""`, and a JSON null decodes to `vim.NIL`.
Every one of those is **truthy** in Lua, so `if name then` — the check used in
most of the browser, AI and session code — treats a name that names nothing as
a bound target. Five of the six commits are one family; the sixth is the same
rule applied to a directive *value*. `util.named` (`lua/poste-db/util.lua`) is
the single spelling of the rule the modules `nav_ui`, `sql_runner`, `explain`,
`completion/data` and `introspect/table` already applied by hand.

## Bugs fixed

1. **A full-width column header left no room for the sort arrow**
   (`buffer/render.lua`, commit `c3e3c00`). Every cell is
   `" " .. name .. " "`, so a column whose name is the widest thing in it has
   exactly one space before the next separator. The sort-indicator splice
   dropped a fixed two bytes after the trimmed name and ate the separator's
   leading byte: the header showed an orphan UTF-8 continuation byte where the
   box-drawing bar had been, and every column right of it shifted one cell out
   of alignment with the data underneath. The arrow now spends only the padding
   it finds — two cells get the spaced form, one the narrow form, none leaves
   the header alone.

2. **A routine rename that matched nothing still reported the new name**
   (`db_browser/copy_ddl.lua`, commit `a030d8b`). Pasting a routine renames it
   by substituting the source name inside the definition text the server
   printed, and that substitution compared against the *bare* name only. Every
   spelling the catalog does not use bare went unrenamed — a Postgres name
   needing quotes (`"Add Two"`), a MySQL name whose backtick `SHOW CREATE`
   doubles, an mssql name in brackets — so the statement created the routine
   under its **source** name, and on Postgres `CREATE OR REPLACE` replaced the
   existing one, while the progress dialog and summary both announced the copy
   under the name the user asked for. The target name was also written back
   bare, so `My Report` reached the server as invalid SQL (or, on Postgres, as
   its own lower-case form). Both sides now go through `ident.quote`, matching
   how the paste engine already spells table and view names; an empty name on
   either side leaves the definition alone instead of building `public.(`.
   Measured on the pre-fix module: that spec ran **36 passing / 12 failing**.

3. **A directive with no name still chose the database**
   (`constants.lua` and the five directive readers — `context`, `file_exec`,
   `nav/route`, `introspect/route`, `ai/actions` — commit `f44d0f2`). `-- @connection` /
   `-- @database` need a value, but the matcher accepted a whitespace-only one:
   `%s+(.+)` captured the blanks an editor left after the word and `vim.trim`
   emptied the capture to `""`. Because resolution takes the *nearest*
   declaration, a placeholder line inside a `###` block overrode the file-level
   directive above it — the block ran against the server's default database
   while the file said `analytics`. Go-to-definition and the DDL route asked
   for the definition of a connection named `""`; `:PosteDbRunFile` reported
   `Connection '' not found` for a file the CLI answers with "No connection
   specified" (`extract_connection_directive` in `exec_file.rs` trims the
   capture and skips the line). `constants.directive_value` now says which name
   a line declares (nil for a nameless one) and is distinct from
   `match_directive`, which still answers "is this a directive line?" — what
   rewriting one in place needs. 8 named failures against the pre-fix sources
   across 6 specs.

4. **An empty connection or database name is not an AI target**
   (`util.lua`, `ai/{system_prompt,actions,schema,init}.lua`, commit `5320683`).
   Each reader on the AI ring tested only for nil, so the envelope's `""` was
   taken for a bound target: the system prompt announced "the chat is scoped to
   connection " with nothing after it and, because the chat scope wins, hid the
   SQL buffer's own context behind it; `actions.resolve_target` handed `""` to
   the executor (a `connection "" not found` instead of the "nothing is bound"
   hint) and turned an empty database into `--database ""`, which the CLI
   applies as `replace_database_in_url` — for sqlite, a fresh **empty** file;
   `ai/schema` kept a second cache entry for the same effective target
   (`""`/`""` versus `?`/`(default)` are different keys). 12 tests, each failing
   against the pre-fix sources (3 util, 4 system_prompt, 4 actions, 1 schema)
   and nothing else.

5. **A name that names nothing no longer reaches the CLI**
   (`session_conn.lua`, `db_browser/{async,operations,actions,copy}.lua`, commit
   `21c6fef`). Browser fetches and session starts built `--database` behind
   `if database then`, while those names come straight off a listing row or a
   connection node's meta: `""` means "this connection's own database" and a
   JSON null is `vim.NIL` — both truthy, both handed to the binary. Probes
   against the pre-fix modules:

   | case | pre-fix | post-fix |
   | --- | --- | --- |
   | blank database on an introspect | `--database <>` in argv, `database: ""` in the journal | flag absent, entry carries no database |
   | `vim.NIL` name in `run_introspect` | raises: `async.lua:71: invalid value (userdata) … for 'concat'` | callback still fires |
   | `vim.NIL` database in `session_conn.get` | raises: `session_conn.lua:23 attempt to concatenate a userdata value` | session starts |
   | `copy.introspect_ddl` with a nil db | a hole in the table constructor: argv ends with a bare `--database` | flag absent |
   | URL carries its own database, buffer has no `-- @database` | pool miss on every statement (`reused=false`), a second session forked per run | `reused=true`, one job |

   The last row is a pool bug the argv derivation had been hiding: `M.get` keyed
   the pool on the caller's raw value while `start` stored the session under the
   URL-inferred name, so the persistent session — whose whole purpose is keeping
   `SET`/`USE` and temp-table state — was never reused. `session_target` now
   derives the effective database once for both the pool key and the command
   line, and only an explicitly named database becomes `--database`.
   13 tests, 11 failing pre-fix (the contrast cases pass before and after).

6. **An unnamed schema no longer corrupts generated SQL**
   (`db_browser/{ops_sql,ops_drop,operations}.lua`, `exec_run.lua`, commit
   `3fc3782`). `ops_sql.qualified_table_ref` trusted any truthy
   `meta.schema`: `ident.quote` returns the empty name unchanged, so the prefix
   was still joined and every generated statement read
   `ALTER TABLE ."users"` — a syntax error on Postgres for a table the user can
   see in the tree — while a JSON null reached `name:gsub` as a userdata and
   raised inside the menu action (`ident.lua:11`). Both drop paths re-spelled
   that rule inline (and threaded a `schema_prefix` nobody read) and had the
   same hole; they now share the one builder. `build_directive_lines` emitted
   `-- @connection ` / `-- @database ` for blank names — a directive that
   selects nothing, sitting in front of the statement as if it named a target —
   and `operations.rename` had copied that header by hand twice and drifted with
   it, so it uses the shared builder now. `exec_run.build_cmd` guarded `""` but
   not `vim.NIL`, and its lone-`USE` shortcut counted `opts.database = ""` as a
   pinned target, sending the statement to `exec-file` (which filters USE out)
   so the context never switched and nothing ran. 12 tests, 8 failing against
   the four files at `21c6fef`.

## Probed, held (recorded on purpose)

- `lex.find_use_database` already returns nil for `""` in all three branches
  (quoted, bracket-quoted, bare) — no fix needed.
- `resolve_full_context` already guards `config.database ~= ""`.
- `context.handle_use_statement` decodes `{"type":"use","database_name":…}`, but
  no Rust producer of that shape exists and `exec_file.rs` filters USE
  statements out of exec-file runs: the hook is effectively dead. Left alone —
  it is the executor's contract, not this bug family's.
- `semantic_diagnostics` passes `--database db` unconditionally. Probed: the
  value comes from the resolve/config paths, which are clean after `f44d0f2` and
  `5320683`, so `""` cannot reach it. Held as a known guard gap rather than
  papered over with a second check at the leaf.
- `context.get_status_text`'s `[db: conn/]` rendering for an empty database is
  cosmetic and unreachable on the same grounds.
- Round 61's "state.context hygiene" item is closed by `f44d0f2`: after that
  commit nothing writes an empty `database_name` into `state.context.database`.

## Still open from earlier rounds

- Cross-dialect routine paste. An earlier note here claimed ClickHouse and mssql
  definitions "are matched by the Postgres/MySQL spellings only" — that is wrong
  on both halves, and this is the correction. `a030d8b` made the substitution
  dialect-aware: the non-MySQL branch spells both sides through
  `ident.quote(name, dialect)`, so mssql brackets and ClickHouse backticks are
  the spellings it looks for (the mssql case is pinned in
  `sql_db_browser_copy_ddl_spec.lua`). And there is currently no live path to
  fail: `catalog.routine_names_sql` returns nil for any dialect other than
  mysql/mariadb/postgres, so the browser lists **no** routines on mssql or
  ClickHouse and a paste can carry none. What is open is the missing feature
  (enumerate those catalogs), not a quoting bug.
- Postgres names carrying a doubled quote.
