# Audit — 2026-11-03 (round 6)

Two read-only subagent audits ran in parallel (A: ai/session/log/statusline/
statement/dml/diagnostics small modules; B: introspect/highlights/nav/
edit_commit/import/editor/db_browser wiring). Per `sql-audit-harness`, every
finding below was re-verified by hand — site read, path traced, headless probe
where one was possible — before any fix. Several subagent claims did not
survive that step and are listed in §4.

Also fixed from the round-5 backlog: the `rerender_dataset_page` /
`view_indices` item (§1.1), previously recorded as "not done".

Result: 132 spec files green (`tests/run.sh` exit 0, 0 failures), luacheck
clean apart from the long-standing `explain.lua` empty-branch note.

## 1. Fixed — data loss / wrong data

1. **`o`/`dd` snapped a sorted or filtered view back to table order** (P1,
   round-5 §5). The editor's post-insert/delete redraw read `layout.rows`
   directly, ignoring `view_indices`: `o` on a sorted dataset redrew the page
   in table order, and the queued row — not in the view — was drawn nowhere,
   leaving the cursor on a line that now showed a REAL row (a following `dd`
   then marked that real row deleted). `num_pages` never moved with the row
   set either (a 50-row result read P:2/1 after `o`). Row-window decision
   extracted to `buffer.page.render_current_view` (one place for every
   redraw-from-state caller), with `dataset.view_append_row` /
   `view_remove_row` keeping `view_indices`/`filtered_indices` in step.
   45b7f10
2. **`extract_table_name` answered the wrong clause** (P1). The keyword
   patterns were tried in a fixed order (FROM, then UPDATE, then INTO), so
   `UPDATE t SET … FROM src RETURNING *` answered src, `INSERT INTO t
   SELECT … FROM s` answered s, `UPDATE t SET c = (SELECT max(v) FROM s)`
   answered s, and MERGE's `THEN UPDATE SET x = 1` answered "set" — and the
   DML builder aimed the user's edits at that table. The earliest reference
   wins now. 269ddb2 — and 8a23d87, the follow-up the round caught on itself:
   without word boundaries, `last_UPDATE FROM film` (Sakila, every table)
   captured the FROM position and answered "from". Both spec'd.
3. **SQLite composite primary keys updated every row sharing the first
   column** (P1). `pragma_table_info` reports `pk` as the column's 1-based
   position in the key; the parser read it as `== 1`, so with
   `PRIMARY KEY (a, b)` column `b` went unflagged and `dml.build_where`
   identified the row by `a` alone — one cell edit rewrote both rows
   (verified against sqlite3). Any value above zero counts now. a98aaa0
4. **Edits typed during a commit's flight were silently discarded** (P2).
   The completion callback resets the committed tab's edit_state and
   refreshes from the server; the in-flight flag only gated a second
   `<leader>w`. A per-tab mark now refuses `i`/`o`/`dd` until the outcome
   lands (per tab, because the reset only touches the committed tab).
   7b8c64b
5. **A cell-edit prompt wrote into whichever tab was current at Enter** (P2).
   The editors captured only row/column indices; a slow query's response or
   an AI render replaces the active tab while the prompt is open (the tab is
   not dirty yet). The tab is captured and threaded through now; a stale
   answer is refused with a notice. 1716d61
6. **`gd` sent a postgres schema-qualified reference to a database named
   like the schema** (P2). `nav/detect` folded the dotted prefix into
   `database` (`app.users` → "Database 'app' not found") although
   `navigate_to_table` has a schema path; the introspect sibling had already
   fixed the same fold on 2026-10-30 — the two parallel resolvers drifted.
   The prefix rides on `schema` now and `nav/handlers` reads it as a database
   only for MySQL-style dialects (new `constants.dotted_prefix_is_database`).
   3056fc3 — same commit fixes `K` on quoted table names, which sent
   `` `users` `` to `poste introspect --table` verbatim ("No DDL found").
7. **`get_stmt_sql` joined lines with a space, so a `--` comment swallowed
   the statement's tail** (P2). `SELECT a, -- first   b FROM film` →
   `extract_table_name` nil → the whole result set lost its DML editing;
   the AI's error context carried the commented-out form. Newline join.
   61e39da
8. **`database_from_url` read a `/` inside the query string as the path**
   (P2): `sslrootcert=/etc/ssl/ca.pem` (standard verify-full form) named the
   database "ca.pem". Query string stripped first. 61e39da
9. **`USE "a""b"` resolved to database `a`** (P3): a doubled quote is the
   escape, the reading the bracket branch already applied to `]]`.
   61e39da
10. **The AI result-set payload sent `vim.NIL` and `table: 0x…` to the
    model** (P2), and a null column name raised `table.concat` on `a` (P3).
    `format.cell_to_string` — the renderer's own rule — is exported and
    shared; column names go through `util.named`. 61e39da

## 2. Fixed — runaway work, robustness

11. **An empty introspect listing spawned `poste introspect` forever** (P1).
    An empty `[]` was cached but read back as "never fetched"; the fetch
    counted as success and re-ran the update — one binary spawn + database
    connection per event-loop turn (measured: 126 spawns in 500 ms with a
    stub binary). Triggers: a connection pointed at a fresh database, and
    per table for `--type columns` (a view the user may not describe).
    Listings are marked fetched now; an empty answer is final. Also: the N
    column fetches of one pass each released the per-buffer slot and
    re-ran the update while the others were in flight (~N²/2 spawns on a
    cold join); the slot releases once, on the last. 7377273
12. **`dml_guard.to_plain` copied the whole syntax tree to read two
    levels** (P3): hundreds of thousands of tables per debounced update for
    a 10k-row `INSERT`. Bounded to the classifier's depth. 3cf05f9
13. Import: a null `type/extra/name` from the browser's JSON kept vim.NIL
    through the `or` fallbacks and crashed the column mapper — the browser
    runner now clean_nils like the introspect runner. A hand-edited journal
    line with a non-numeric edit summary raised `%d` on expand; a literal
    `%` in a filter text was evaluated as a statusline item. Esc on the
    "Nullable?" / "Default value" prompts read as "no" and carried on — no
    way out of the sequence. `parse_json` reported the pcall verdict
    ("Invalid JSON: true"). 6ebfeb1, 61e39da
14. **EXPLAIN ran against the binary's default connection when resolution
    failed** (P3): the resolver's second return (tunnel down, unresolved
    `{{VAR}}`) was discarded. Now warns with the reason and stops. The
    dead `readfile` guard in nav/handlers is pcall'd; the "OK" tint is
    word-bounded (TOKYO no longer greens); `K` on a column typed in the
    other case resolves; blink's `BlinkCmpKind*` links are `link_if_empty`.
    6ebfeb1

## 4. Verified — claims that did not survive

- **`edit_commit.exec.decode_json` is dead** — has a spec
  (`sql_edit_commit_exec_spec`); a test reference is a live surface per the
  harness. Same for `introspect.detect`'s public `find_block_for_line`
  wrapper (`sql_introspect_detect_spec`). Both kept.
- **Caching `environ()` in `get_env_vars`** (the statusline hot path's
  dominant cost) — tried, then reverted: `vim.env.X = ...` changes the live
  process environment (the precedence specs set and clear OS vars mid-test),
  so a snapshot goes stale. Memoizing `get_ctx_color` on (conn, epoch)
  without reading config would trade TOML-edit freshness for speed — a
  product call, recorded here, not taken unilaterally.
- **A schema-qualified sqlite layout name breaks `pragma_table_info`** —
  no confirmed production path produces one (the browser passes the bare
  node name); the failure mode is the safe all-column WHERE. Watching, not
  fixed.
- **`import/execute` passes a nil connection URL on** (B, inferred) — could
  not confirm the Rust side's behavior without a pin; the commit path's
  explicit refusal does not exist here. Left open, worth a probe with a real
  binary.

## 5. Not done, and why

- **`session_conn` sends every statement of a sequence before any verdict**
  (A, inferred): a failed `SET @var` prelude does not stop the dependent
  statement on the Lua side. Sequential send (next payload from the previous
  `on_response`) changes throughput for the common all-succeed case; needs a
  decision plus a real binary to verify against.
- **`session_conn` stdout accumulation is O(n²)** for large single-line
  results (A#8): the chunk loop re-scans from byte 1. Real, but the fix
  rewrites the event parser; deferred with the existing per-request-watchdog
  item.
- **`resolve_full_context` per statement** (A#11): one full-buffer read per
  statement per update on the diagnostics path. The fix re-shapes the
  context API's contract; deferred.
- **`statement_indicator`'s zero-work shortcut never fires for one-line
  statements** (A#18) and **`dml_guard`'s dollar-tag scan is O(n²)** (A#41,
  measured 30 ms/60 KB) — small, real, left for a perf round with the two
  above.
- **The three `### block` finders with three marker rules** (B#14) and **the
  two detect resolvers** (B#15) — consolidation started with this round's
  fixes but full unification is a refactor with its own spec pass.
- Copy-conflict probes, postgres pk metadata in the Rust, session watchdog:
  earlier rounds' cross-repo items, unchanged.
