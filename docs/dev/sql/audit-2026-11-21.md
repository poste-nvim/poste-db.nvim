# Audit — 2026-11-21 (round 8)

Three read-only audits ran in parallel, split by domain:

- **A — AI chat & completion**: `lua/poste-db/ai/*`, `completion/*`
- **B — introspection, browser, navigation, highlights**: `introspect/*`,
  `db_browser/*`, `nav/*`, `highlights/*`, `log_viewer.lua`, `import/*`
- **C — dataset buffer & editor view**: `buffer/nav*`, `editor/nav.lua`,
  `semantic_diagnostics.lua`, `format.lua` render path

Out of scope by design (recently audited in rounds 5–7): paging, search,
history, header, the browser's table listing/edit flows, editor cell/column
editing, the SQL parser.

Baseline before this round: HEAD `e2acbd1`, clean tree, 135 spec files
green, luacheck 4 warnings / 0 errors (all four pre-existing). **Every
finding below was re-checked by reading the code; several sub-agent claims
did not survive that check and are recorded in §4. Result after the round:
138 spec files, 2477 cases, 0 failures; luacheck unchanged at 4 / 0.**

## 2. Shared components (the duplicated logic from this round)

- **`poste-db/schema_cache.lua` + `poste-db/ddl.lua`** — one invalidation
  choke point and one DDL classifier, now used by the response hook, the
  browser DDL path and the AI chat. `ddl.lua` has no dependencies on purpose:
  `response.lua` is loaded under a stub-heavy spec and must not pull in
  `ai/*`.
- **`util.each_line`** — replaced 11 copies of
  `(s .. "\n"):gmatch("(.-)\n")` (`format.lua` ×2, `buffer/render.lua`,
  `buffer/nav_preview.lua`, `log_viewer.lua` ×7). CRLF/blank-line semantics
  now change in one place.
- **`util.fuzzy_match(text, pattern, with_positions)`** — the subsequence
  matcher was copied in `completion/ctx.lua` and `db_browser/actions.lua`;
  `ctx` delegates, the browser calls `util` directly.
- **`width.display_width_capped`** — column-width measurement that stops at
  the 30-cell ceiling (see §3).

## 3. Performance — measured first, then changed

- **Rejected claim**: the C audit said the `<null>`/`<default>` substring
  scan runs on every row regardless of the 1000-row row-number deferral.
  Measured (3000/10000/20000 rows): 1.6 / 5.2 / 10.9 ms — linear and small.
  Not changed; the 1000-row extmark deferral stays the only threshold.
- **Column width planning** (`format.calc_column_widths`): every cell was
  JSON-encoded and measured in full, then clipped to `MAX_COL_WIDTH = 30`.
  1000 rows × 6 wide-JSONB columns: plan 66.8 ms, render 73.5 ms, total
  144.1 ms. Added `width.display_width_capped` (short-circuits as soon as the
  prefix reaches the cap — wide ASCII hits it immediately) and a weak-keyed
  `encoded_tables` memo so a table cell is encoded once. After: plan 56.8 ms,
  render 60.8 ms, total **120.9 ms (−16 %)**. `width_spec` covers the five
  boundary cases.

## 4. Verified — claims that did not survive, or were deliberately not taken

- "`0` and `""` originals also break the `and/or` fallback" — false: in Lua
  only `nil`/`false` are falsy. `old_val` can't be `nil` (it is only stored
  when a value exists), so boolean `false` was the only real case.
- The per-row highlight scan cost above — measured negligible.
- `semantic_diagnostics` cache key `conn .. "/" .. db` normalization
  (`lower()`): would merge genuinely case-sensitive hosts/databases. Left as
  is; the key builder is at least single-sited.
- `_updating` as a module-level lock and `_pending_checks[buf]` surviving
  buffer wipeout: the update body is synchronous and runs from the main loop,
  so the contention/stale-slot window is inferred-only. Recorded, not changed.
- Raw overlay (`nav_raw`) reading `layout.rows` instead of
  `view_indices`: may be intentional ("raw table"). Needs an author decision
  on whether "raw" means *raw* or *current view*.
- `winbar` calling `name_for_url` (O(connections)) on every render: with
  realistic connection counts the cost is noise.
- `\t` in cell values: `cell_to_string` is shared with AI context and export;
  escaping tabs changes the fidelity of those paths — a product call.
- Introspect argv builder / `pick_table_match` / detect payload DRY: those
  payloads are asserted byte-exactly in specs and stubbed elsewhere; merging
  them buys little and risks the stubs.

## 5. Not done, and why (backlog)

| Item | Why not now |
|------|-------------|
| Client watchdog for `exec`/`session` requests | Needs a transport-level timeout/abort contract (and a cancel story for the Rust session), not a local patch. Today a wedged binary waits forever. |
| JSON big integers lose precision (`vim.json.decode`) | Requires token-level number parsing or a custom decoder; all other fields depend on the current decoder. |
| CJK identifier prefixes in completion | Only affects the non-Rust fallback path (the binary returns the prefixes). |
| `resolve_current_context` per completion request | Whole-buffer scan per keystroke, but the fix threads context through four fetchers; no baseline measurement yet. |
| Non-zero exit still renders whatever `items` arrived + a notification | The comment says it is deliberate (partial results beat nothing); the cache keeps the first response. |
| Tab width, diagnostics lock/slots, winbar lookup, raw view | See §4 — all recorded with the reason. |

## 8. Lesson for next round

The two real bugs of this round (#1 and #2) share a shape: **a second entry
point into the same executor**. Chat execution duplicated the runner's
post-DDL work instead of calling it, and the AI schema fetch cached a failure
as data. When a subsystem gains a second caller, the audit question is not
"does the new path work" but "which side effects of the first path did it
forget" — that is what produced both stale completions and the empty-schema
session.
