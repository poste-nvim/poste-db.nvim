## 1. Fixed bugs (3 commits)

### 1. Committing an untouched new row produced an invalid INSERT (49b3891)

Adding a row with `o` in the dataset and committing it without filling in a
single cell made `dml.generate_insert` produce
`INSERT INTO "t" () VALUES ();` — a syntax error on every engine except
MySQL, surfacing as a bare server error. It now produces the legal form per
dialect: postgres/sqlite/mssql use `DEFAULT VALUES`, MySQL/MariaDB keep the
empty-list spelling (the engine accepts it), and ClickHouse — which has no
default-value INSERT form — rejects it explicitly. The `generate_dml` insert
call site handles the new nil return the same way (reason recorded in the
`skipped` list instead of producing a `{ sql = nil }` statement).

### 2. MySQL text columns had ISO timestamps silently rewritten (49b3891)

`dml.quote_val`'s MySQL path rewrote `2024-01-01T10:00:00Z` into
`'2024-01-01 10:00:00'` without regard for the column type: committing a
VARCHAR cell changed the stored value, and the same rewrite inside the WHERE
clause made the statement no longer hit the row it was aiming at. The rewrite
now happens only when the column type mentions time/date (or when the caller
has no type information, preserving the old behavior).
Reproduction: `UPDATE \`t\` SET \`memo\` = '2024-01-01 10:00:00' WHERE
\`memo\` = '2024-01-01 10:00:00'` with the column declared varchar.

### 3. Timestamp display lost the sub-second part (8618ca1)

`format.format_datetime_local` matched only whole seconds, so
`2024-01-01T00:00:00.123456Z` rendered in local time with `.123456` gone —
two values 200ms apart in a timestamp(6) column displayed as the same second.
The sub-second part now survives the conversion.

### 4. Closing one buffer killed sessions of OTHER databases on the same connection (5605d66)

`session_conn.cleanup_buf` called `M.stop(key)`, and `M.stop` fans out by URL
— closing the sessions of ALL databases on that connection. With two buffers
connected to different databases of one server, closing the first buffer also
killed the session the second buffer was using: in-flight requests reported
"SQL session exited" and all `SET`/temp-table state was lost. `cleanup_buf`
now closes by individual pool key (the new `stop_one`); the URL fan-out is
kept only for `:PosteDbSessionStop <url>`. The same fix removed a
pairs()-while-removing-other-keys bug in the same function (undefined
behavior in Lua; `stop_all`'s comment had documented that rule all along,
`cleanup_buf` just never followed it).

## 2. Re-checked and found NOT problems (recorded so the next round does not re-suspect them)

- **A trailing backslash in a toml.lua literal string** (`p = 'a\'`) —
  verified by probing: it parses correctly (returns `a\`), and
  `strip_inline_comment`'s state machine deliberately does no escape handling
  for literal strings; documented as intentional.
- **`dialect_table_exists_sql`'s else branch falling back to sqlite_master** —
  mssql/clickhouse would get sqlite's probe SQL here, but `catalog.enumerate`
  rejects both dialects further upstream with "Unsupported dialect for copy",
  so the path is unreachable. If copy ever supports mssql, the
  information_schema probes belong here (see section 4).
- **`local next` shadowing the global in `import/format.parse_csv`** — the
  repo luacheck config (`.luacheckrc`) is at 0 warnings; accepted style,
  untouched.
- **`db_browser/copy.lua` name-conflict probing fails closed** (reports
  "exists") — deliberate: on a permission-restricted information_schema it
  must not treat a taken name as free and then overwrite it.
- **`log_viewer.get_entry_at_cursor` checks buf validity but not win** — the
  float has `bufhidden = "wipe"`, so a closed window always takes the buffer
  with it; the lifecycles are identical and the "buf valid, win gone" state
  cannot occur.
- **`dataset.compute_view_indices`'s mixed-type sort comparator** — probed
  with 6 mixed types (number/string/bool/nil/numeric strings): the order is
  stable and consistent, nil always sorts last, no "invalid order function"
  risk (NaN arrives as text through the JSON transport and never enters the
  comparison as a double).
- **`format.wrap_line` at width=0** — oversized words overflow one per line;
  the comment records the choice.
- **Performance**: `width.display_width` has a byte-length fast path for pure
  ASCII; `format_datetime_local` computes the local timezone offset once per
  timestamp cell (4 os.time/os.date calls, microseconds) — not worth caching.

## 4. Observations (uncertain real-world impact; untouched)

1. **`copy_ddl.dialect_table_exists_sql`'s dialect gap** — unreachable today
   (see section 2), but it is "the first thing to break when copy supports a
   new dialect". When extending copy, add the mssql (`sys.tables`) and
   clickhouse probes with it.
2. **`exec_run.run_sql` (the sync path) after the 30s timeout** — when
   `vim.system`'s timeout fires, `result.code` can be nil and the failure
   message becomes "exec-file exit code nil". Message readability only; no
   behavioral impact.
3. **`export.format_json` with a column named JSON null (vim.NIL)** —
   `tostring(col.name)` would produce the key `"vim.NIL"`. A real binary
   never sends a null resultset column name; only a hand-made response gets
   there. Untouched.
4. **`exec_run.is_query_sql` does not recognize a statement starting with a
   paren** (`(SELECT 1) UNION ...`) — it is only the tie-breaker after the
   Rust-side QueryKinds decision (see the comment above the function); a
   misjudgment additionally requires the driver to omit both columns and row
   count. Untouched.
