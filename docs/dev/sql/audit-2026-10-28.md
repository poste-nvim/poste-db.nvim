## 1. Fixed bugs (8 commits)

### 1. A cancelled run invalidated a still-running request's response (de2a4b5)

`sql_runner.run_sql_request` bumped `exec_seq`, cleared indicators, pushed a
history entry and cleared the panel BEFORE the missing-connection and
DML-guard cancel paths. Consequences of a cancelled run: (1) the epoch bump
made the stale-seq guard in `sql_runner/response` silently DROP the response
of a request that was still in flight (a successful query showed nothing);
(2) an empty history entry appeared; (3) spinners/panel were wiped for a run
that never started. Every "the run actually starts" mutation now sits after
every cancel path, next to `session.begin` — which is what the old comment
already claimed.

### 2. `state.last_error.sql` grew without bound (9a24c5d)

In the multi-result failure branch, `get_stmt_sql`'s max_end argument was
`visual_sel_end or #buf_lines` while the success branch had
`... or stmt_end or ...` — a non-visual multi-statement run's error context
(what the AI ask-about-this-error action sends) ran to the end of the buffer.
The `stmt_end` fallback is now in place.

### 3. `vim.NIL` broke into `file_exec` in three places (8efeefd)

Executing a SQL file against a browser node whose `meta.database` is a JSON
null decoded to `vim.NIL` — truthy and `~= ""`: it landed on jobstart's argv
as a userdata (soft failure), raised inside the progress dialog's
`.. S.db` concatenation, and was recorded to the SQL journal verbatim. The
regression test caught the argv site first; running it then caught the dialog
site as a SECOND bug. The root fix normalizes `conn`/`database` through
`util.named` at `run()` entry (the same armor `exec_run.build_cmd` has). The
same commit keeps the previous `total` when an event omits it
(`string.format("%d", nil)` raised bare inside the job callback) and drops
the write-only `S.current_sql`/`S.total_rows` fields.

### 4. `config.merge` index-merged list-valued options (f5a0bf5)

`vim.tbl_deep_extend("force")` merges arrays by index:
`setup({ sql_formatters = { "pg_format" } })` kept the three excluded default
formatters as fallbacks (the list `source_format` picks from) with the new
entry duplicated at position 4 — a shorter list could never shrink the
default. List-to-list now replaces wholesale; an empty table still merges (a
no-op for lists; the "no keymap overrides" reading for maps).

### 5. Four connections problems (cb060c4)

- **Picker rows dropped the `tunnel` field**: `format_connection`'s lock mark
  and `run_test`'s tunnel-routed testing read `conn.tunnel`, but
  `list_connections`' row builder never carried it — both were dead for every
  picker-sourced connection.
- **`apply_env` did not expand nested tables**: `tunnel = { to = "{{BASTION}}" }`
  handed the literal `{{BASTION}}` to `tunnel.ensure`, so the failure read
  like a tunnel problem instead of a config one.
- **`env.json` had no cache**: `get_env_vars` runs on every statusline
  evaluation and cursor move; dotenv had an mtime cache while env.json did
  find_file_upwards + readfile + a JSON decode per call. Same cache added
  (keyed including `current_env`).
- **sqlite `path = ""`**: `conn.path or ":memory:"` never fired for the empty
  string, producing the invalid URL `sqlite:?mode=rwc`. Empty now means unset.

The same commit merged the four hand-written copies of "the current file
buffer's directory, else cwd" (connections/commands/health/completion-data)
into one exported `connections.get_search_dir()` with a buftype guard: pseudo
buffers (`poste://dataset`, `poste://db_browser`, `health://`) have a
non-empty but non-file name, and the old rule resolved their search root to
`poste:`/`health:` — the statusline and `:checkhealth` could read a different
connections.toml than the SQL file being edited.

### 6. Five db_browser defects + two smaller ones (9c58a8e)

- **`db_browser/completion.lua` indexed a function**: `filter_types` bound
  `adapter.completion_item_kind` (a function) and took `.TypeParameter` off
  the binding — "attempt to index a function value" on every keystroke-level
  type completion in the Modify/New Column forms. It calls it now.
- **The paste TARGET's dialect fell through to the yank's**: a table node
  under a sqlite connection carries no `meta.dialect` (only connection and
  database nodes do), so `resolve_paste_target` landed on `entry.dialect` —
  the SOURCE's dialect — and a postgres yank pasted onto sqlite passed the
  dialect-mismatch guard while postgres-flavored catalog/DDL SQL ran against
  sqlite. The walk-up's connection node now wins before the yank.
- **An exactly-8-item paste plan printed "... and 0 more"** (`i >= 8` still
  fired after the eighth item was fully listed).
- **`run_ddl_and_refresh`'s on_error did not refresh the subtree**:
  `refresh_subtree` clears the target's children and sets loading BEFORE the
  job starts, so a transport failure (reported once via on_error per the
  exec_run contract) left the node stuck on the loading marker forever.
- **The journal's and-or chain**: with a result parsed but stderr non-empty,
  `parsed_result and nil` fell through to `err_text` — SUCCESS rows carried
  an error message. Rewritten as an explicit if.
- **`extract_table_name` counted JOIN inside identifiers**: only the char
  BEFORE was checked, so `SELECT joined_at, join_date FROM users` counted two
  JOINs and returned nil, degrading the label to "result n". Both word edges
  are checked now.
- **Directive completion had no word boundary**: a typo like
  `-- @connectionX` matched the branch, found no name after the directive and
  offered every connection. The branch check now anchors on whitespace or
  end-of-line.

### 7. Dead code removal and stale comments (3284fa2)

Deleted (each verified by enumerating every require alias before grepping):
`constants`' `RAW_MODE_WINBAR`/`INTROSPECT_FLOAT_EXTRA_HEIGHT`/
`STATUSLINE_TRUNC_WIDTH`, `dataset.tab_count` (buffer's own, used, remains),

`db_browser/notify.error` (failures notify directly with the PLUGIN_TITLE
everywhere else), `source_format`'s four `detect_cmd` fields (detection uses
`vim.fn.executable`).

Stale comments corrected against the code: `exec_run`'s header said
`poste.cli`/`poste.state` but the requires are `poste-db.*` since the family
dissolution; `session_conn`'s "classification mirrors
exec_run.build_response" was not true (the sequence aggregator never adopted
`is_query_sql` — see section 3 D1) and now describes the actual rule and
where to reconcile; `handlers`' header pointed at completion.lua (now
completion/init.lua); `completion/init`'s cache-key comment now names the
real key; source_format's header no longer implies conform integration is
wired by setup() (it is three opt-in public functions); every remaining
"connections.json" comment (context.lua, edit_commit, buffer/init,
db_browser/actions, one test) says connections.toml; `sql_multi_stmt_spec`
dropped its try_ts_stmt_ranges claim (production find_stmt_lines no longer
calls it).

### 8. The three dialect resolution copies merged (113dacc)

`diagnostics.lua` and `syntax.lua` carried byte-identical `get_dialect`
copies, and `source_format.resolve_dialect` a third fork that silently
dropped the `g:poste_db_dialect` fallback — formatters got `""` (each
formatter's own default dialect) while diagnostics honored the user's global
option. `lua/poste-db/dialect.lua` is now the single implementation; all
three delegate, and the chain (### header → connection config → global
option → filetype) is pinned by a spec. `diagnostics` loads dialect.lua at
the top so the sql_diagnostics_spec stubs for context/connections are
captured; `syntax` binds it as `dialect_mod` (two functions take a `dialect`
parameter that would shadow the module binding).

## 2. Re-checked and found NOT problems (recorded so the next round does not re-suspect them)

- **`buffer/nav.lua` using `strdisplaywidth` in the navigation path**
  (:138, :187) — per LEARNINGS #16: cursor movement and partial repaints
  follow nvim's own grid, so `strdisplaywidth` IS the correct oracle for
  navigation; dataset rendering's truncation goes through width.lua. The two
  oracles coexist by design.
- **`import/format.lua`'s parsing is already hardened**: BOM stripping, CRLF
  inside quotes kept per RFC 4180, a stray quote only opens a quoted region
  at field start, TSV empty edge cells preserved, nested JSON values encoded.
  Every hostile input constructed this round errored or parsed as expected.
- **The AI modules' poste-ai dependency**: every entry pcalls
  `require("poste-ai")` or sits behind `available()`, and the plugin's absence
  is a silent skip — no bare requires (submodule skew handled in d6454c7).
- **`compat.lua` does not fire spurious deprecation warnings** for
  `g:poste_db_*` names: `opt()` checks the new key first and warns once, only
  on the legacy key.
- **No `tunnel.lua` process leaks**: failure paths kill the ssh process,
  config mismatch restarts via `M.stop`, `stop_all` is on VimLeavePre, and
  `can_connect` always closes its socket.
- **`toml.lua`'s password-safe choices**: values and error messages are never
  echoed; the earlier round already flipped most fail-open edges to
  fail-closed, and this round closed the rest (see D12).
- **`session_conn`'s pairs()-while-removing loops** all snapshot the keys
  first; the comment records the rule.
- **All `autocmds.lua` groups use `clear = true`** — repeated setup does not
  stack.

## 3. Recorded findings, and what became of them

Performance:

- **P1 3-6 full-buffer context resolves per keystroke**: six
  `data.conn_key()` call sites in `completion/handlers.lua` passed no ctx
  while `data.resolve_current_context` goes straight to
  `context.resolve_full_context` (a full-buffer scan, uncached). FIXED in
  10c311b: every ensure_* fetch delivers the ctx it resolved with as the
  callback's last argument.
- **P2 semantic diagnostics resolved the full context once per statement**
  (the statement loop in `semantic_diagnostics.lua`, plus the default ctx
  earlier) — S statements × L lines per 300ms debounce. FIXED in 10c311b:
  `context.resolve_context` caches per buffer|changedtick|line (hits return a
  fresh copy; callers may mutate).
- **P3 the three syntax highlighters re-scanned the whole buffer on every
  TextChanged with no debounce** (autocmds.lua). FIXED in 10c311b for the two
  tree-sitter sweeps (150ms per-buffer debounce); directive highlighting
  stays synchronous for immediate feedback.
- **P4 formatting blocked the editor up to 10s per candidate** (source_format's
  vim.system wait). FIXED in 10c311b: the first candidate keeps 10s, every
  fallback gets 3s.
- **P5 db_browser forced `redrawstatus` on every CursorMoved** (its
  statusline.update). FIXED in 10c311b: unchanged text skips the write and
  the redraw.
- **P6 the dataset winbar was built twice per render with four forced
  redraws** (finalize_rendered_page, then render_dataset). FIXED in c165a2d:
  unchanged-text caches on both the winbar and the SQL statusline.

Design/correctness — all fixed in d27143a unless noted:

- **D1 three response classifiers diverged** (exec_run.build_response,
  session_conn's single path, session_conn's sequence aggregator) — unified
  on `verdict.carries_resultset`: columns or rows decide before the affected
  count (schema.md: a SELECT always ships columns). The session single path
  previously ignored columns entirely; exec_run keeps its SQL-shape tiebreak
  layered on top.
- **D2 introspect jobs had no timeout** (a hung binary wedged completion
  fetches and semantic checks until restart) — both flush/settle false after
  15s and stop the job.
- **D3 semantic schema fetches had no epoch guard** (an in-flight fetch could
  re-cache the pre-DDL schema after invalidate()) — invalidate bumps an
  epoch; fetches capture it at start and discard stale landings.
- **D4 the DML-keyword walk had no visited set** (two DML keywords in one
  ERROR node re-entered each other forever; the stack overflow was swallowed
  by the update pcall, silently dropping diagnostics) — a per-walk visited
  set bounds it.
- **D5 statement's forward `;`-scan crossed ### block boundaries** (an
  unterminated statement in block A swallowed B; the synthetic block carried
  two markers and the Rust exec ran B too) — bounded now, matching the
  backward scan.
- **D6 the diagnostics debounce timer was one module-global** (buffer B's
  keystroke cancelled buffer A's scheduled run; self-healing but lossy) —
  per-buffer now, mirroring sql_runner's `_cursor_moved_timers`.
- **D7 lex block-comment nesting was read three ways** (`depth_after` nested;
  `is_comment_or_string` and `blank_regions` did not) — all three are
  single-level now; postgres-only nesting is the documented known exception,
  and the spec pins the agreement.
- **D8 db_browser multi-select keyed on node identity** (a refresh replaced
  children; markers vanished while the winbar count and `p`/`D` still
  iterated stale nodes) — render prunes selections against reachability from
  the current roots.
- **D9 copy_progress keyed results by label** (a postgres trigger legally
  shares its table's name; two same-label jobs read/wrote one slot) — keyed
  by job position now; `errors` stays label-keyed on purpose (same-name items
  merging into one summary line is acceptable).
- **D10 db_browser DRY groups** — six hand-rolled invalidate-refetch-redraw
  blocks (five paste/clone sites + refresh_by_conn) now go through
  util.refresh_subtree via init's refresh_tree_node, with the statusline
  repaint moving through a context hook; the three root-walk dialect copies
  collapsed into `util.connection_dialect` (the yank keymap's copy also
  matched a TABLE named like a connection) and the table_ops callback reuses
  `util.find_table_node`.
- **D11 exec-chain DRY** — `sql_log.wrap_callbacks` is the one journal-wrap
  seam (executor.lua and exec_run.lua carried byte-identical copies) and the
  journal uses `verdict.UNEXPLAINED_FAILURE` instead of a third wording.
- **D12 toml.lua's residual fail-open edges** — unknown escapes now error
  (verbatim before; a deliberate, spec-documented behavior change),
  `\uXXXX`/`\UXXXXXXXX` decode, garbage after a string's real closing quote
  (`"a" "b"`, `"a\"`) errors, and bare values carrying whitespace (`k = 1 2`)
  error.
- **D13 (kept as-is) the copy_progress and ops_drop progress/summary dialogs**
  remain two implementations. Unifying them changes focus/cancel/summary UX
  that headless specs pin only at the dialog contract level — per LEARNINGS
  #9 that migration needs a real-session verification step, so it is deferred
  deliberately rather than half-done.
