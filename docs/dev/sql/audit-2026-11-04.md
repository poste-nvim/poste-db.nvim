# Audit — 2026-11-04 (round 7)

Two read-only subagent audits ran in parallel (A: format/width/source_format/
lex/ident/dialect/toml/connections/dataset/context/verdict/types/util/constants/
async/cli/log/sql_log/dml_guard/dml; B: db_browser subtree, export, import,
table_ops/float_window/dialog/select/indicators/statement_indicator, help/
health/insert_hint/explain/tunnel/install, editor cell+column, buffer page/
search/history/header). The execution chain (statement/ts_stmt/sql_runner/
response/exec_run/session_conn/buffer init+render/editor nav/completion data/
handlers) was read line-by-line in the same session, outside the subagents.

Per `sql-audit-harness`, every finding below was re-verified by hand before
any fix — site read, path traced, headless probe where one was possible.
Claims that did not survive are in §4. Both agents' scopes were chosen to
avoid round 4–6 coverage; their reports listed known/deferred items as
already excluded.

Result: 132 spec files green (`tests/run.sh` exit 0, 0 failures, 18 new
regression assertions), luacheck clean apart from the long-standing
`explain.lua` empty-branch note.

## 1. Fixed — events dropped, crashes

1. **Unbuffered jobstart chunks were parsed as byte fragments** (P1). A
   probe proves the contract: one read carrying `a\nb\nc\n` arrives as
   `{"a","b","c",""}` — complete lines, newlines consumed, trailing ""
   end-of-batch marker. Two parsers assumed raw fragments:
   - `file_exec.lua`'s reassembly concatenated the elements, gluing every
     event of a multi-event read into one undecodable blob — all dropped.
     A summary coalesced with the last result made a successful file run
     report "exit code 0 (no summary event)". Fixed: non-final elements are
     handled as complete lines, the final element flushes or extends the
     held partial. 2 specs (multi-event read, split-across-reads).
   - `session_conn.lua` joined with `""`: a coalesced read produced a
     buffer with no newline anywhere, so the newline scan never fired, the
     tail-parse failed forever, and the session went mute with every pending
     request hanging (no watchdog exists). Join with `"\n"` now rebuilds the
     wire stream; 2 specs (coalesced read, empty lines). In-vivo coalescing
     did not reproduce with the real binary on this machine (writes are
     paced per event), but the unit-level contract violation is proven and
     the fix is spec'd. Also recorded as LEARNINGS #30.
2. **A column whose `"type"` decoded from JSON null crashed every render of
   the response** (P2). `vim.NIL` is truthy, so `plan_resultset_layout`'s
   `if raw then` passed it to `normalize_type`, which raised on
   `raw:lower()`; `format_dataset` is called unpcall'd from five seams, so
   the user saw nothing for an answered query. The producer is real:
   ClickHouse builds `"type": m["type"]` straight off the describe row
   (poste.nvim `crates/poste-exec/src/sql_executor/clickhouse.rs:175`), and
   a row missing the key carries explicit null. Probed red, then fixed
   (`normalize_type` guards vim.NIL; the same armor now covers null
   `results`/`columns`/`rows`, which raised `#userdata` on
   `plan_resultset_layout`). Round 5 §4 had rejected a null-type claim —
   that verdict covered `cell_to_string` only; the ctype path is the live
   one. 2 specs.
3. **The import preview's Esc/q/click-away ended the flow with no answer**
   (P2). `dialog.open`'s own q/<Esc> keymaps and the WinLeave fallback close
   through `on_close`; `show_preview` never passed one, so the callback the
   whole import sequence waits on never fired — Esc silently swallowed the
   flow (no "Import cancelled", same class as the round-6 prompt-sequence
   fix). `on_close` now answers nil once; the scheduled nil cannot overwrite
   a synchronous keymap answer. 2 specs (including the ordering race).
4. **Batch-DROP progress dialog: a stray focus change removed the only stop
   button** (P2). The dialog closed on WinLeave by default, its buffer-local
   `q` keymap died with the wiped buffer, `cancelled` stayed false, and the
   remaining DROPs kept executing invisibly and unstoppably.
   `close_on_leave = false` keeps the dialog (and `q`) up until the run ends
   or is cancelled. Same fix for the paste-progress dialog (cross-server
   SELECT+INSERT kept writing after a focus change). Cancelled batch-DROP
   now also refreshes the tree — the tables already dropped used to stay
   visible until a manual `r`.

## 2. Fixed — robustness

5. **The first callback of every schema fetch ran bare** (P3). The queued
   callbacks of `ensure_tables`/`ensure_tables_for_db`/`ensure_columns` were
   wrapped to deliver the resolved ctx; the first registered callback was
   not, so the flush value (`nil`) landed in the consumer's `fetch_ctx` and
   its `conn_key(nil)` re-resolved the whole buffer context — after a buffer
   switch, against the wrong connection. 3 specs (tables/columns get ctx,
   databases get `(names, ctx)`).
6. **A statement consisting only of a `/* … */` block comment became a
   phantom statement** (P3): `find_stmt_lines` judged content on the raw
   text, so the comment line opened an entry that swallowed the real
   statement below it and shifted every later result's statement mapping;
   `has_sql_content` similarly sent a comment-only span to the binary.
   Both now judge on the `lex.blank_regions` output (which also stops a bare
   quoted-literal line from opening one). 3 specs.
7. **Browser `<CR>` had no in-flight token** (P3): two rapid table opens
   race their exec_run responses and the EARLIER one could win the screen
   against the user's last keypress. A module-level sequence drops a
   superseded response.
8. **`layout._database` took a decoded null verbatim** (P3): the dataset
   edit path concatenates it into a cache key — a raise on every cell edit.
   `util.named`, matching `show_table_info`'s existing armor. Same armor for
   the two hand-built `-- @database` directives in `operations.lua`
   (`new_table`, `add_column`), which raised on vim.NIL and wrote a
   valueless directive on "".
9. **Null names in db_browser listings crashed the whole tree** (P3):
   `make_database_node`/`make_schema_node`/`make_table_node` took
   `item.name` raw — flatten_tree's `" " .. node.name` (and full_name
   concatenation at construction time) raise on the truthy vim.NIL. All
   three go through `null_or(name, "?")` like every other listing field.
10. **The search prompt box had no normal-mode exit and leaked on a manual
    window close** (P3): Esc landed in normal mode where no key answered;
    Ctrl-W c skipped cleanup and the prompt buffer lingered. Normal-mode
    `<Esc>`/`q` close it, and `bufhidden=wipe` is the backstop.
11. **Search-jump callbacks used the browser buffer unguarded** (P3): after
    a manual `:bd poste://db_browser`, `do_jump`'s scheduled callback
    raised on the dead buffer. Guarded.
12. **A stale search survived a non-`M.close` teardown** (P3): Ctrl-W c /
    `:close` bypass `M.close`, and reopening + `n` rendered the OLD tree
    (the search context held the previous root list) into the reused
    buffer. Every `M.open` now wipes the search state first (clean case
    pays one early-return guard).
13. **`introspect_ddl` answered nobody on a clean, empty run** (P3,
    low-confidence item confirmed by reading): exit 0 with zero stdout
    fired neither on_result nor on_error — the paste stayed at "copying"
    forever. on_exit now reports "No DDL output from introspection".
14. **Export notified with a `vim.NIL` row count** (P3): a decoded null
    `row_count` is truthy, `string.format("%d", …)` raised — after the
    file was already written. `tonumber` first, both sites.
15. **Small**: `buffer/init.lua`'s empty `if tab.is_sorting` branch
    inverted; `exec_run`'s inline USE response replaced by
    `make_use_response(use_db, conn_url)` (the two builders had drifted
    into byte-similar copies).

## 3. Fixed — data integrity, perf

16. **TOML inline tables silently kept the last duplicate key** (P3):
    round 5 added the "Duplicate key" error for top-level sections;
    `parse_container`'s inline branch still last-won —
    `tunnel = { to = "a", to = "b" }` quietly connected through "b". Same
    error, same rule. 2 specs.
17. **`apply_page_bounds` with a hand-built `page_size = 0` produced
    inf/-nan** (P3): `or 1` only covers a MISSING size; the infinity flowed
    into num_pages/page and poisoned every later page computation. Size 0
    degrades to 1 (finite math). 1 spec.
18. **The journal carried unbounded SQL** (P3): run-file mode stamps the
    whole file's text on the entry — a 5 MB file was one 5 MB JSONL line
    the viewer read back whole. `sql` capped at 2000 bytes, `error_msg`'s
    existing 500-byte cut switched to `util.utf8_safe_cut` (a plain byte
    cut sliced CJK characters in half and ended entries in invalid UTF-8).
    2 specs.
19. **Search highlighting froze on non-paginated datasets** (perf, P2-ish):
    `apply_search_highlights` looped over ALL matches — a common string on
    a 10k-row result meant tens of thousands of get_lines calls and
    extmark pairs per render and per n/N jump. The non-paginated pass now
    windows 1000 extmarks around the current match (the one n/N lands on
    is always drawn); the match list and the winbar total are unchanged.
20. **`constants.match_directive` rebuilt its pattern per call** (perf):
    pesc + concat on every header line of the context-resolution path.
    Compiled patterns are memoized per name. 17 constants specs still
    green.
21. **The history sidebar computed each entry's timestamp twice** (perf):
    `format_wallclock` + `display_width` ran in build_lines and again in
    the highlight pass; the start column is carried over now.

## 4. Verified — claims that did not survive, or were not taken

- **verdict.carries_resultset's `affected_rows == nil` is dead on the live
  envelope** (A, inferred): true — the binary writes `"affected_rows":
  null` for every read, which never equals nil. Treating null as "no
  count" instead would classify a bare `SET` (also null-affected, no
  columns) as a resultset and render an empty grid instead of Query OK —
  a more common regression than the gap it closes (a 0-row SELECT whose
  describe-recovery produced `columns: []`). The docstring now states the
  actual rule and the residual gap; recorded, not changed.
- **Cancel on the paste-progress dialog consumes the yank register**
  (B#4): real (cancel_copy → close → on_close → on_complete → yank.clear).
  Both readings are defensible — clearing prevents a re-paste of
  half-written state, keeping it enables retry — and no consumer hangs on
  either. Product call, recorded, not taken.
- **`forms_advanced.close_active` skips the replaced form's on_cancel**
  (B#14): verified, but both current callers pass no on_cancel and the
  wiped buffer already takes the keymaps — zero harm today. Watch, not
  fixed.
- **`source_format.format` reads visual mode from the current window while
  applying to `bufnr`** (A, inferred): the only production caller is the
  buffer's own keymap (bufnr == current buffer). The guard would matter
  only for a future cross-buffer caller. Watch, not fixed.
- Two format.lua nil-guards (translated_sql footnote, render_row non-table
  row) from the agent's low-confidence list: the producer fields have no
  Rust writer (grep), and the render_row shape needs a malformed response
  plus an edit action — recorded in the agent report, not fixed.

## 5. Not done, and why (perf points, recorded)

- **`plan_resultset_layout` scans all rows twice and re-renders cells at
  draw time** (A): the plan pass's strings are not reused by render_page;
  JSON cells pay a vim.json.encode per cell per pass on the FULL row set.
  Real on 10k-row results, but caching plan strings changes the layout
  contract the editor and page render both read — a refactor with its own
  spec pass.
- **`import/format.parse_csv` scans char-by-char** (B): ~10M sub+insert
  for a 10 MB file. A find-based segment scanner is the fix, but the CSV
  state machine (quotes, embedded newlines) is the importer's tested
  core; deferred with a benchmark first.
- **`import detect_format` decodes JSON twice** (B): probe decode +
  parse_json. One decode would need parse_json split into decode + row
  mapping; win is one decode per large import. Deferred.
- **`insert_hint.update` re-reads from buffer top on every debounced cursor
  move** (B), **statement_indicator paints one extmark per statement line**
  (B), **db_browser tree re-reads the buffer per rendered row** (B),
  **indicators sign_getplaced scans per sign op** (B), **prefetch_children
  spawns 2N processes per expanded database** (B, design), **completion
  conn_key re-resolving on cache miss** (A, same shape as round 6 §5):
  recorded with the agent reports; each needs either a measured hot path
  or a contract change to be worth touching.
- The pre-existing round-6 deferrals (session_conn O(n²) re-decode,
  resolve_full_context per statement, statement_indicator shortcut,
  dml_guard dollar scan) are unchanged — note the O(n²) item's practical
  surface shrank with fix #1: complete events are consumed by the newline
  scan, so only the in-flight partial is re-parsed.
