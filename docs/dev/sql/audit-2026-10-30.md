# Audit — 2026-10-30 (round 4)

Three read-only subagent audits ran in parallel over the areas the 2026-10-28
round had not covered line-by-line: (A) the execution & data path
(statement/executor/session/exec_run/connections/edit_commit/semantic
diagnostics), (B) the dataset UI + top-level wiring (format/buffer/statusline/
log_viewer/autocmds/config/compat), and (C) db browser / completion / import /
export / introspect / AI. Every finding below was re-verified by hand (site
read, trigger traced) before any fix was applied — subagent output is treated
as hypothesis per `sql-audit-harness`. Known deferrals from the 2026-10-17 /
2026-10-28 reports were excluded up front.

Result: 2464 spec assertions green (`tests/run.sh` exit 0), including the new
regression specs listed at the end.

## 1. Fixed — execution & data path

1. **A lone `USE` with any pinned target died at the binary** (P1).
   `exec_run.lua` gated its local-USE shortcut on `has_target(opts)`, and
   `has_target` counted a resolved `conn_url` as a pin — so the most common
   configuration (a buffer with `-- @connection`) routed a bare `USE` to
   exec-file, whose Rust side filters USE statements and bails when nothing
   remains ("No executable SQL statements found"). The context never
   switched. The pin makes no difference: a lone USE cannot be executed by
   the binary under any argv, so the local shortcut now fires whenever
   `detect_use` matches the whole statement, pins or not. `has_target` was
   deleted (both call sites were the USE branches; grep-verified).
2. **`commit_edits` had no in-flight guard** (P1). `edit_state.dirty` is
   cleared only when the response lands, so a second `<leader>w` / `:w`
   during the flight re-dispatched the identical DML batch — a plain INSERT
   wrote duplicated rows. A module-local `commit_in_flight` flag now engages
   at dispatch and is released in `on_response`, `on_error` and the
   failed-start branch (exec_run delivers exactly once per run).
3. **Dead `or deps.buf_content` fallback in `sql_runner/response.lua`** (P2).
   `statement.get_stmt_sql` returns `""` (never nil) for an index past the
   statement list, so `... or deps.buf_content` never fired and a
   result/statement-count divergence recorded `state.last_error.sql = ""` —
   the context the AI ask-about-this-error action sends.
4. **Semantic diagnostics scheduled at most ONE column fetch per update
   pass** (P2). The per-buffer in-flight flag was re-checked inside the
   scheduling loop, so the first fetch's flag swallowed every remaining
   entry (and a tables fetch earlier in the pass swallowed all of them).
   Convergence cost one full buffer re-walk per table. The check now happens
   once, before the loop, and only when there is something to fetch.
5. **`ts_stmt._span_cache` never evicted closed buffers** (P3). bufnr values
   are never reused and a closed buffer is never passed to `find_stmt_span`
   again, so every closed SQL buffer leaked its full span list until
   restart. The cache is now bounded by a wholesale wipe at 64 inserts (the
   same shape as `context._resolve_cache`; it is a leak bound, not an LRU).
6. **An undecodable session line was dropped in silence** (P3). One lost
   result event parks that request's callbacks forever (there is no
   per-request watchdog on the session transport); the log line is now the
   trace a desynced/truncated event leaves.
7. **`table_ops` told every DDL-insert user to press `<leader>rr`** (P4) —
   a keymap that exists nowhere. The notify now names the actual run keymap
   from config.
8. `lex.is_comment_or_string` carries a TEST-ONLY header comment: zero
   production callers, and its backslash reading disagrees with the two live
   scanners (removal is a product decision; the comment prevents a silent
   re-wiring).

## 2. Fixed — dataset UI & wiring

1. **`track_cell_edit`'s revert branch dropped `dirty` while added/deleted
   rows were pending** (P1). The recompute looked only at `modified_cells`;
   an `o`-queued INSERT became silently uncommittable (`:w` did nothing) and
   tab switches unblocked. Same three-way recompute as
   `track_row_delete`'s cancel path now.
2. **Three dead keymap branches in `buffer_setup.lua`; lazy-loaded first
   buffer had no completion triggers** (P1). `nav.show_ddl` /
   `nav.format_sql` / `nav.trigger_completion` exist nowhere (nav/init.lua
   exposes only `goto_definition`), so the branches never fired — K and
   `<leader>ff` worked only because `ensure_sql_keymaps` binds them
   independently. Deleted the dead guards. The completion trigger wiring
   (`<C-Space>` keymap + INSERT auto-triggers + `blink_cmp_min_keyword_length`)
   lived ONLY in the BufRead handler, which does not fire for a buffer read
   before `setup()` (lazy-load with `ft = "poste_sql"`); it is now one
   idempotent `setup_completion_triggers(buf)` called from both the FileType
   and BufRead handlers, guarded by a buffer var.
3. **Recreated dataset window lost its winbar and SQL statusline** (P2).
   The unchanged-text caches (`_last_winbar_text`, `_last_sql_statusline`)
   were never reset when the panel was closed and reopened with identical
   content, so the brand-new window skipped both option writes. The caches
   now reset in `ensure_dataset_window` when a window is actually created,
   and the per-render winbar write at the old bypass site goes through the
   cache guard (that bypass was load-bearing for recreation only — exactly
   the hole the reset closes).
4. **`delete_history_entry` was the one history path that did not block on
   dirty edits** (P2). Deleting the ACTIVE entry destroyed its queued
   INSERTs/UPDATEs/DELETEs with no warning while `switch_tab` /
   `switch_history_entry` both refuse. Same `EDIT_CONFLICT_MSG` guard now.
5. **`log_viewer.render()` returned before `update_winbar()` when the filter
   matched nothing** (P2) — the winbar kept advertising the unfiltered count,
   and an empty journal never showed the key help at all.
6. **lualine's `get_context_hl` lacked the `vim.b.poste_db_conn` first-read
   the mini path documents as mandatory** (P2) — a dataset context string has
   no `/` to split on, so lualine lost the per-connection color on every
   dataset buffer.
7. **Deferred row-number highlights could paint stale positions** (P2). For
   pages > 1000 rows the scheduled pass checked buffer validity but not
   whether another render ran in between; the stale pass re-added tints
   computed from old line positions with nothing clearing them. The pass now
   compares `changedtick` (extmark writes do not bump it, text writes do).
8. **Search / filter / column-yank read `rows_source` without the
   malformed-row guard their siblings have** (P2). A non-table row raised in
   `compute_matches` (killing the whole search), the filter loop, and
   `collect_column_values` (killing the yank). They now read the malformed
   row the render path's way: no matches / skipped / all-NULL respectively.
9. **`normalize_entry` hardened every field except the one that gets
   indexed** (P2): `edit_summary = 5` in a hand-edited journal line raised
   "attempt to index a number value" on expand. Non-table `edit_summary`
   values now drop.
10. **History sidebar forced `redrawstatus` on every j/k** (P3) — the same
    per-keystroke shape the 2026-10-28 round removed from db_browser. The
    built text is now cached, and the cache resets when the sidebar opens
    (a new window has no statusline — the same stale-cache class as item 3).
11. **`entry_database` re-resolved the connection config up to three times
    per entry per render** (P3, ~3000 `apply_env` builds at the 1000-entry
    cap). Memoized per render.
12. **Every context-menu / form open leaked one unlisted scratch buffer and
    one ungrouped autocmd** (P3). Fresh float buffers now get
    `bufhidden = "wipe"` (log_viewer's established idiom; caller-supplied
    `opts.buf` keeps the caller's lifecycle), and the WinLeave autocmd is
    grouped per open.
13. Stale claims: the `history_prev` fallback keymap said `"<leader>b"`
    (default is `"<leader>p"`); `help.lua` matched a `PosteDataset` filetype
    nothing sets; the README's `compat.lua` row claimed variable-name
    fallbacks that don't exist and `statement_indicator` was described as
    sign-column (it paints a background rectangle / gutter tint).

## 3. Fixed — browser / completion / export

1. **The paste/clone DDL fetch was schema-blind** (P1). `introspect_ddl`
   never passed `--schema`, and the binary's postgres DDL arm defaults to
   `public` — the yanked `app.events` fetched public.events's DDL: a
   same-named public table was silently recreated and copied IN ITS PLACE,
   otherwise the paste errored "No DDL found". The source schema now rides
   through `introspect_ddl` (`--schema`), the view definition fetch (scoped
   `pg_get_viewdef` lookup), the routine definition fetch (scoped
   `pg_get_functiondef`), the legacy multi-select path (items now carry
   `meta.schema`), and the recomposed `CREATE VIEW` is schema-qualified the
   way the table DDL already was.
2. **`sql_escape_val` rendered numbers with `tostring`** (P1). LuaJIT's
   `%.14g` turns an exact 15-digit integer (123456789012345, well under
   2^53) into `1.2345678901234e+14` = 123456789012340 — the SQL INSERT
   export silently shifted the key on re-import. This is the exact trap
   `ident.quote_literal` already fixed and documented for DML generation;
   the export path now routes numbers through it, and the CSV/TSV cell
   formatter emits the full decimal form for integral doubles. (`vim.json.encode`
   was probed and is lossless — format_json needed no change.)
3. **`gd` on a schema-qualified postgres table passed the SCHEMA as
   `--database`** (P1). `introspect/context.lua` folded the schema into the
   `db` slot in three branches, and `show_table_ddl` emitted
   `--database <schema>`, which the CLI applies as
   `replace_database_in_url` — the connection repointed at a database named
   like the schema ("database app does not exist"). The schema now rides on
   a separate `schema` field (context → target → init → table.lua), which
   argv-lays per dialect exactly like `column.lua` already did: `--schema`
   for postgres/sqlite, `--database` for mysql/mariadb (where a schema IS a
   database). The pinned spec expectations for the folded shape were
   updated deliberately (documented in the spec).
4. **`colu` (alter modify column) postgres template was invalid SQL** (P2):
   `ALTER COLUMN c SET <type>` does not exist; the type change is
   `ALTER COLUMN c TYPE t` (separate statements for NOT NULL / DEFAULT, the
   shape `ops_sql.build_alter_column_sql` already emits).
5. **`clear_cache` resolved "the current connection" from the focused
   buffer** (P2): browser-side DDL executes while the BROWSER window is
   focused, so the completion cache survived a CREATE/DROP. `clear_cache`
   takes an explicit connection; `invalidate_completion_cache(conn)` passes
   the connection the DDL ran on (`run_ddl_and_refresh`, `execute_drop`,
   batch drop).
6. **Modify Column with a cleared Default field bound `DEFAULT ''`** (P2).
   There was no path to DROP a default. Postgres now emits
   `ALTER COLUMN c DROP DEFAULT`; MySQL/MariaDB omit the DEFAULT clause
   (MODIFY redefines the column whole — omitting the clause drops the
   default; there is no inline `DROP DEFAULT` on MODIFY).
7. **`new_table` hardcoded a postgres-flavored template for every dialect**
   (P2): on sqlite `SERIAL` is neither auto-increment nor a rowid alias
   (inserts without `id` stored NULL), and MSSQL's `TIMESTAMP` is the
   deprecated rowversion synonym. Per-dialect starter columns now mirror
   the variants `snippets.lua` already carries for `ct`.
8. **The directive→connection fallback item builder existed twice,
   byte-similar** (P2 smell) — extracted to `connection_fallback_items`,
   zero behavior delta.
9. **`execute_table_select` resolved config discovery from `getcwd()`**
   (P3) unlike every other browser fetch — with the browser open over a SQL
   file in another directory it read a different `connections.toml` than the
   same node's other actions. Uses `get_search_dir(context.source_buf)`.
10. The `syntax.lua` module header described a quarter of the module (it
    also owns digit-prefix recoloring, log-line highlighting and the
    hand-maintained known-error mirror of `ts_stmt.find_error_nodes`).

## 4. Verified clean / not problems (so the next round does not re-suspect)

- `vim.json.encode` is lossless for integral doubles (probed headless:
  123456789012345 round-trips) — format_json needs no number armor.
- `vim.json.decode` tolerates trailing `\r`/`\n`, so CRLF does not trigger
  the session's undecodable-line path; only genuinely malformed JSON does.
- The vendored transports' failed-start double-delivery guard, the journal
  exactly-once seams and the session pool's stdout state machine held up
  under re-reading (2026-10-28 round confirmed again by subagent A).
- `float_window` callers were enumerated before the `bufhidden = "wipe"`
  change: forms/context_menu close windows only and read the `fields` table
  (not buffer lines) at submit; header.lua already re-creates on
  `nvim_buf_is_valid(buf) == false`; log_viewer sets the same option itself.

## 5. Not done, and why

- **Postgres columns carry no `pk`/`key`** (P1, cross-repo). The binary's
  postgres `Columns` arm emits name/type/nullable/default/max_length/comment
  /fk only — mysql emits `key`, sqlite emits `pk` — so every PK-dependent
  branch (column tree PK icon + ordering, `update_template`'s WHERE,
  `insert_template`'s PK offer, import's null-PK pre-validation) silently
  degrades on postgres. The `list_indexes` query selects `indisunique` but
  not `indisprimary`, so no Lua-side derivation is reliable either. Fix
  belongs in poste.nvim's Rust `list_columns` (join `table_constraints` like
  the existing FK query) — recorded here as the cross-repo contract change
  to make; NOT hacked around Lua-side.
- **No per-request watchdog on the session transport** (P3): the binary's
  "every request line gets exactly one response" contract plus the epoch
  bump on the next request contain the wedge in practice; the dropped-line
  log (§1.6) is the minimum honest trace. Revisit only if session hangs are
  reported in the wild.
- **Copy conflict probes stay one round-trip per item** (P3 perf): a
  whole-database clone costs N sequential `information_schema` queries
  before the confirm dialog. A per-target listing query would fix it, but
  it reworks `resolve_conflict_names`' callback shape — deferred as its own
  change.
- **`render_dataset` still builds the winbar twice per render** (both builds
  are cache-guarded now; only the redundant raw option write was removed).
  Collapsing the two builds means reworking `finalize_rendered_page`'s
  contract with its other callers — left for a dedicated pass.
- **No spec pins the buffer_setup/completion wiring on a lazy-loaded first
  buffer** (the FileType+BufRead overlap needs a full autocmd simulation);
  the fix is small and reviewed, but the wiring gap itself is only covered
  indirectly today.

## 6. Test surface

New regression specs (one per fixed bug where the seam is testable):
`sql_exec_run_spec` (lone USE with a resolved connection / a pinned
database), `sql_runner_response_spec` (last_error.sql falls back to
buf_content when the result index has no statement entry),
`sql_edit_commit_spec` (second dispatch refused in flight; dispatches again
after release), `sql_semantic_diagnostics_spec` (both uncached tables fetch
columns in one pass), `sql_editor_spec` (dirty survives cell-revert while an
add/delete is pending), `sql_statusline_spec` (get_context_hl reads
b:poste_db_conn on a dataset-shaped context), `sql_export_spec` (15-digit
integer exact in INSERT and CSV), `sql_db_browser_operations_spec`
(DROP DEFAULT on emptied field, postgres + mysql),
`sql_snippets_spec` (colu postgres TYPE spelling),
`sql_introspect_context_spec` (schema no longer folds into db — deliberate
expectation-shape change), `sql_introspect_table_spec` (--schema vs
--database per dialect), `sql_db_browser_fetch_argv_spec` (copy
introspect_ddl carries --schema), `sql_buffer_search_spec` (non-table row
skipped, view positions stable), `sql_buffer_nav_cell_spec` (non-table row
yanks as NULL), `sql_log_viewer_spec` (non-table edit_summary drops).
